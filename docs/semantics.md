# Implemented semantics

The references are pinned in [compatibility.md](compatibility.md). Tests in
`tests/runtime.test.mjs` use reviewed manual examples and pinned source behavior;
expectations are not generated by running this interpreter.

## Values and numeric profiles

Values retain distinct tags for integer, float, string, object, error, list and
map. Lists/maps are immutable; indexed writes rebuild the path to the local
variable, preserving aliases. The codec stores integers as decimal strings and
preserves negative floating zero. LambdaMOO selects signed 32-bit integers;
ToastStunt selects signed 64-bit integers (the reference also permits 32-bit
builds). Literals outside the selected range fail compilation.

Arithmetic has no implicit numeric coercion. Mixed arithmetic raises E_TYPE,
except float exponentiation permits an integer exponent. Division truncates
integers toward zero. Division/remainder by zero raises E_DIV. Integer arithmetic
wraps in two's complement at the selected width, including division overflow.
This is an explicit portable policy where the reference uses C signed arithmetic
whose overflow is not portable; it does not claim every server build agrees.

LambdaMOO remainder follows the numerator's sign; the pinned ToastStunt remainder
follows the divisor's sign (`src/numbers.cc`). Integer negative powers generally
produce zero, with special cases for 0 and +/-1. The pinned ToastStunt source
reverses the parity for negative powers of -1; this implementation preserves that
profile-specific behavior and tests it. Float NaN produces E_INVARG in LambdaMOO
and E_FLOAT in ToastStunt; infinity produces E_FLOAT in both. Gradual IEEE
underflow produces finite values or zero. Boundary tests cover overflow, NaN, subnormal values and signed underflow.
ToastStunt also preserves its source formula for float remainder, including
precision loss for a very small numerator and large divisor. This is not a claim
of exhaustive bit-identical libm behavior across every server platform.

## Equality, truth, names and strings

Equality does not coerce tags: 7, 7.0 and #7 differ. Strings compare with ASCII
case folding, recursively inside lists/maps. `equal(a,b)` is case-sensitive.
Ordering requires matching scalar tags and rejects collections; error ordering
uses the standard error-code order. Nonzero numbers and nonempty strings/lists/
maps are true; all objects and error values are false. `&&` and `||` short-circuit
and return operands. Conditional expressions evaluate only the selected branch.

Variable names are case-insensitive. Every invocation gets independent locals;
missing variables raise E_VARNF. Type names (INT, NUM, FLOAT, STR, LIST, OBJ, ERR,
and ToastStunt MAP) start as the corresponding integer codes and can be assigned.
Context supplies this/player/caller/args/verb. Command-context strings default to
empty and dobj/iobj to #-1; no command dispatch is implemented.

Source string literals currently support printable ASCII plus tab. Other
characters receive a compile-time unsupported-feature diagnostic. Escape syntax
quotes the following character; it does not use JavaScript newline escapes.
Host constructors and snapshots accept arbitrary UTF-16 strings. Operations on
that data count UTF-16 code units: an emoji occupies two indices, and slicing can
produce a lone surrogate. Comparisons fold only ASCII A–Z; accented characters
retain their distinction. Output preserves the original text and counts the same
units for its budget. This is an explicit host-data extension, not a claim of
byte-for-byte non-ASCII behavior on a MOO server. Source literals, including
comment strings, retain the printable-ASCII/tab restriction. `toliteral` is a
display function for extended host strings; use the JSON codec for persistence.
Source spans count UTF-16 positions, independently of this language restriction.
`tostr` uses collection summaries and human-readable error messages; `toliteral`
recursively formats tagged values and escapes strings. Float formatting uses 15
significant decimal digits, matching the reference DBL_DIG setting; exhaustive
libc rounding equivalence is not claimed.

## Collections

List/string indexing is one-based; slice ends are inclusive. `$` means the length
of the nearest enclosing indexing/slicing collection, including nested index
expressions. Reversed extraction returns an empty sequence before range checks.
Replacement follows the manual's prefix/replacement/suffix rules; end positions
beyond the original length may append. Missing map keys raise E_RANGE.

Map keys must be scalar and compare case-insensitively. Entries sort by the
reference internal scalar type order (int, object, error, float, string), then
value; a later equivalent key replaces both key spelling and value. Numeric key
comparison uses mathematical ordering, avoiding the reference C subtraction's
possible overflow/truncation. List membership returns the first one-based match.
ToastStunt also searches substrings and map **values** with `in`; LambdaMOO only
supports list membership. `mapkeys`, `mapvalues`, `maphaskey`, and `mapdelete` are
implemented. Requested keys in `mapvalues` are case-sensitive, matching the pinned
source; default `maphaskey` and deletion are case-insensitive.

## Flow and exceptions

If/elseif/else, while, list/range for, break, continue and return execute against
the owned AST. Named loop control supports for variables; the upstream grammar
does not support all named-while spellings. Fall-through returns integer zero.
Scatter assigns required/optional/rest targets, prioritizes optional positions
left-to-right, and evaluates missing defaults after non-default assignments.
An optional without a default preserves its previous variable value. Splicing
requires a list and is supported in lists, calls and exception code lists.

Error constants are values; raising one is separate. Inline catches and except
code expressions run before their protected body. The first matching except
handles a raised MOO error. Handler data contains code, message, value and a
traceback list. Tracebacks contain receiver, verb, programmer, defining object,
player and line-number fields through the catching frame. Finally runs on ordinary flow,
return, loop transfer or MOO error; its own transfer overrides the earlier one.

Resource exhaustion and host failures bypass both MOO catches and finally, so
cleanup cannot suppress a limit or continue an exhausted run. Deterministic
budgets count evaluation steps, expensive comparisons/formatting, collection and
string allocation, expression/call depth, output and world storage. Worker
cancellation and transactional state transfer are implemented; see workers.md.
Unsupported AST constructs are rejected before execution even in dead branches.

## Explicit compatibility boundaries

World properties, verbs, frames/pass, inherited clear slots, programming and
inspection APIs, and output now have execution coverage; see [worlds](worlds.md)
for boundaries. Snapshots and host verb registrations are now implemented;
worker transactions and selected reviewed corpus execution are implemented.
Lifecycle hooks are explicitly rejected. Source-position and host-text boundary
tests cover both profiles. Lexical grammar differences remain documented
limitations of the pinned parser; they are not silently approximated. Academy
app adoption is validated separately; see academy-integration.md.
Direct/worker result encoding now has shared depth/count/string bounds, with
controlled failures; worker snapshot capacity is reserved from world quotas.

## String search built-ins

`index(source, needle [, caseMatters])` returns the first one-based occurrence;
`rindex` returns the last; no match is zero. Case comparison folds ASCII by
default. The optional flag uses MOO truth, including false object/error values.
The empty needle matches at one for index and length+1 for rindex.
Each attempted position and character comparison consumes steps, so repeated
prefixes cannot bypass the execution budget.

ToastStunt additionally accepts integer offset as a fourth argument, following
pinned `src/list.cc`: index skips a nonnegative prefix and returns a position
relative to that suffix; rindex shortens the search prefix with a nonpositive
offset. An offset outside the string raises E_INVARG, an explicit safe boundary
for reference C pointer arithmetic outside valid storage. LambdaMOO rejects a
fourth argument with E_ARGS. Dedicated tests cover these profile differences.
